## 2. スキーマ v2

```jsonc
{
  "version": 2,
  "architecture": {
    "layout": "grid",            // "grid" | "hex"（省略時 grid）
    "columns": [                 // 旧 groups。列見出し。並び順＝列の並び
      { "id": "lane_1", "label": "フロントエンド" }
    ],
    "nodes": [
      { "id": "node_1", "label": "...", "type": "frontend",
        "col": 0, "row": 2,      // 整数。省略時は自動配置
        "colorToken": "color_1", "icon": "react" }
    ],
    "edges": [
      { "from": "node_1", "to": "node_2", "label": "API",
        "bidirectional": false }  // 省略時 false
    ]
  },
  "flow": { "tasks": [...], "connections": [...] }   // 変更なし
}
```

### 2.1 v1 からの変更点

| v1 | v2 | 変換ルール |
|---|---|---|
| `groups` | `columns` | そのまま改名 |
| `laneOrder` | （廃止） | `columns` の並び順に反映 |
| `node.group` | `node.col` | 自動レイアウトで解決された列番号を書き込む |
| `node.rowOrder` | `node.row` | 解決された行番号を書き込む |
| `type: "spacer"` | （廃止） | ノードを削除する（空きマスがそのまま隙間になる） |
| `__human__` 列 | 通常の列 | 人間ノードは自動配置時の既定で左端の列に置くだけで、特別扱いはしない |
| `edge.a` / `edge.b` | `edge.from` / `edge.to` | a→b と読む |

### 2.2 列とノードの関係

- 列見出しは `columns[i]` が列 i に対応する。見出しの無い列もあってよい（見出しが空欄になる）
- 同じマス（col, row）に2ノードがあれば、読み込み時に後のノードを下の空きマスへずらし、警告を出す

### 2.3 自動配置（col/row が未指定のノードだけ）

- 現行の `layoutByLanes`（MinLA による列順の最適化と、行のソート）をそのまま流用し、算出した列・行を書き込む
- 一度確定すれば、以後の自動再計算はしない（ドラッグ結果が勝手に変わらないように）
- UIの「整列し直す」ボタンで、全ノードの col/row を破棄して再計算できる

## 3. グリッド／ハニカム描画（④⑤）

### 3.1 座標変換（`src/graph/gridGeometry.ts`）

```
grid: x = col * CELL_W
      y = row * CELL_H
hex : x = col * HEX_W + (row % 2 ? HEX_W / 2 : 0)   // オフセット座標（奇数行を半マスずらす）
      y = row * HEX_H * 0.75
```

- 逆変換（ドロップ位置 → 最寄りのマス）も同じファイルに置く
- grid と hex の切り替えで変わるのは描画だけで、データは変わらない

### 3.2 ノードの形

| 配置 | 形 | 大きさ |
|---|---|---|
| grid | 角丸の長方形 | 168×64 |
| hex | 尖った頂点が上の六角形（SVG の clip-path） | 幅 150 程度、ラベルは2行まで |

### 3.3 編集操作

- ドラッグすると最寄りのマスへ吸着する。移動先が埋まっていたら入れ替える
- 列見出しの◀▶で、列ごと入れ替える（中のノードの col も一括で書き換える）
- 「+列追加」で、右端に見出し付きの空列を作る
- 空列・空マスにはプレゼンモードでは何も描かない（3章 / 5章参照）
- 編集モードだけ、背景にマスの補助線を出す

## 4. 有向エッジ（⑥）

- アーキテクチャ側のエッジに矢印（`markerEnd`）を付ける
- `bidirectional: true` のときは両端に矢印を付ける
- `LoomArchEdge` の浮動交点計算はそのまま使い、マーカーだけ足す
- ハイライト中は矢印もルート色で塗る
- プロセスフロー側はすでに矢印付きなので変更しない

## 5. 編集／プレゼンモード（②）

- 状態はURLで持つ: `#doc=...&mode=present`。`mode` が無いときの既定は、共有リンクなら `present`、それ以外（新規・サンプル）なら `edit`
- ヘッダー右端のトグルで切り替える（URLの `mode` も書き換える）
- 共有リンクのコピー時は、ダイアログで「プレゼン用」か「編集用」かを選ぶ

| 要素 | 編集 | プレゼン |
|---|---|---|
| マスの補助線・空列 | 表示 | 非表示（空列は詰めて表示しない） |
| 列見出しの◀▶、「+追加」系、整列ボタン | 表示 | 非表示 |
| ドラッグ・ダブルクリック編集 | 可 | 不可 |
| JSON編集・アップロード | 表示 | メニュー内に格納 |
| ステップ操作（次へ・戻る・自動再生） | 表示 | 表示（大きめ） |

## 6. note用PNG書き出し（③）

- ヘッダーのメニュー「note用に書き出す」で、`0018_note_fig` の基準に沿った PNG を作る
  - 幅 1240px
  - 文字 44px 以上
  - 線 6px 以上
  - 1行28字まで
- 書き出し専用の描画（`src/export/NoteFigure.tsx`）を、画面外の DOM に描いてから `html-to-image` で PNG にする。React Flow のビューポートには依存しない
- 書き出しの種類:
  1. **全体図**: アーキテクチャのみ。ハイライトなし
  2. **ステップ図**: 現在のステップのハイライト付きアーキテクチャと、タスク名・説明の帯
  3. **全ステップ一括**: 2を全ステップ分まとめて ZIP にする
- プロセスフローは縦に長くなるので、note用には「タスク名の番号付きリスト」を図の横ではなく下に組む。文字が大きくても28字の制約に収まる
- 6ノードを超えると文字44pxでは横幅が足りないので、そのときは2段組にする。超過は警告で知らせる
